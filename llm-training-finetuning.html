Supervised fine-tuning: teaching it to be an assistant

A base model straight out of pretraining is a very good text completer, not an assistant. Ask it a question and it may just continue the pattern — writing more questions, or drifting into unrelated text — because that's the most statistically plausible continuation of internet-style text. Supervised fine-tuning (SFT) is the (comparatively small, but behaviorally huge) second training stage that reshapes this into "answer directly, follow instructions, stop when done."

2

Instruction-tuning data

What SFT trains on

SFT data is a curated set of (prompt, response) pairs — ideally covering a wide range of task types (question answering, summarization, code, creative writing, multi-turn conversation) and response styles (concise, detailed, step-by-step). For OLMo, Ai2 uses and publishes the Tulu mixture: a combination of human-written examples, carefully filtered existing instruction datasets, and synthetically generated examples, again released with the exact recipe rather than just a description of it.

⚠️ Quality over quantity: unlike pretraining, SFT data is measured in thousands to low millions of examples, not trillions of tokens — and the field's own research (including Ai2's) has repeatedly found that a smaller, carefully curated instruction set often outperforms a much larger, noisier one. Bad SFT examples (wrong answers, inconsistent formatting, sycophantic tone) get imitated just as readily as good ones.

The SFT loss: only score the response

Mechanics

SFT reuses the exact same cross-entropy loss from Part 3 — the only change is which tokens count toward it. Loss is masked (excluded) on the system prompt and user turn, and computed only on the assistant's response tokens, so the model is only ever penalized for generating a bad response, never for "failing to predict" the user's own message (which it isn't supposed to generate anyway).

L = − (1/|R|) ∑ₜ∈R log Pθ(xₜ | x<ₜ)   R = the set of response-token positions only

What SFT changes — and what it doesn't

Scope

SFT is comparatively cheap and fast next to pretraining, and its effect is mostly on behavior and format, not on the underlying knowledge the model has — that was set during pretraining, on vastly more data. Over-training on a narrow SFT set can cause the model to overfit to surface patterns in that set (a fixed response length, a signature phrase, refusing things the SFT data happened to refuse) rather than genuinely generalizing "be helpful." This is also why SFT alone isn't the last stage: it teaches format and directness, but it doesn't have a principled way to say "this response is better than that one" for cases with no single correct answer — which is exactly the gap the next stage, alignment, is built to close.
