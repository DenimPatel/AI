# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Jekyll site published by GitHub Pages at https://denimpatel.github.io/AI/.

Since the Aug 2026 split, the site is one half of a two-repo setup:

| Repo | URL | Holds |
|---|---|---|
| `DenimPatel/AI` (this repo) | `/AI/` | Home, about, the AI record (`ai/*.md`), the field notes (`robotics/**`, `vision/notes/**`) and the `/blog/` index |
| `DenimPatel/interactive-courses` | `/interactive-courses/` | All 15 interactive guide series, the guide kit and per-series domain JS |

There is no JavaScript framework, no npm, and no build step beyond Jekyll. CI
(`.github/workflows/ci.yml`) runs a build, an internal link check and a content linter on
every push and PR; `.github/workflows/pages.yml` builds and deploys. A separate monthly job
checks external links too.

Deep reference material for the guides — the guide kit, `linalg-viz.js`'s matrix library,
`Prob.plot` vs `LinAlg.plane`, the `Stats`/`GenMedia`/`Multimodal` domain layers, the quiz
runner — now lives in the interactive-courses repo's own `CLAUDE.md`. This repo keeps the
record, the notes and the blog.

## Commands

```bash
export LANG=C.UTF-8 LC_ALL=C.UTF-8    # see "UTF-8" below — the build fails without this

bundle install                         # first time only; installs the github-pages gem set
bundle exec jekyll build --safe --trace
bundle exec jekyll serve               # local preview at http://localhost:4000/AI/

# link check — run before and after any move; the failure count must not increase
bundle exec htmlproofer _site --disable-external --swap-urls '^/AI:' \
  --ignore-empty-alt --no-enforce-https

# content linter — warn-only on files that existed before your change, fails only on
# new/changed files (diffed against the default branch); see scripts/lint-content.rb
ruby scripts/lint-content.rb

# cross-repo sync — regenerates _data/guide_index.yml and the old-URL redirect stubs
# from an interactive-courses checkout. Run after ANY guide part is added/removed/
# renamed/re-permalinked there, then commit the result.
ruby scripts/sync-guides.rb /path/to/interactive-courses
```

CI runs the first three. `--safe` matches the GitHub Pages sandbox and rejects
non-whitelisted plugins, so always build with it. `--swap-urls '^/AI:'` strips the
`baseurl` so html-proofer can resolve links against `_site`.

**UTF-8:** Ruby defaults to a US-ASCII external encoding in this environment, and the build
dies with `Invalid US-ASCII character "\xE2"` on the site's em-dashes. Export `LANG` and
`LC_ALL` as above. GitHub Pages builds with UTF-8, so this is a local-only concern.

## Architecture

### `_data/` is the source of truth, not the pages

Almost nothing structural is written by hand in a page. Before editing markup, check
whether the thing you want to change is generated:

| File | Owns |
|---|---|
| `_data/sections.yml` | The four top-level sections (`ai`, `vision`, `robotics`, `blog`) — drives the global nav, the homepage doors, and every section hub. **No `series:` keys**: the guides are not in this repo. |
| `_data/note_groups.yml` | Grouping and ordering of the field-note listings, per section, including the `blog`/`perspective` group for pure-opinion posts |
| `_data/{timeline,products,benchmarks,labs,quotes}.yml` | The AI record content, rendered by both `/ai/<page>/` and the homepage teaser |
| `_data/guide_index.yml` | **Generated.** One entry per guide in the companion repo (title, absolute URL, part count) plus `total_parts` / `total_guides`. The homepage reads it because `site.data.series` no longer exists here. |

The homepage counters are computed from these files. **Never hardcode a count** — the
previous hardcoded "85 releases" had drifted from the actual 73. The guide counts come
from `site.data.guide_index`, never from a literal.

### The cross-repo sync step (read this before touching a guide)

`_data/guide_index.yml` and the static redirect stubs are both generated by
`scripts/sync-guides.rb` from a checkout of `interactive-courses`. The repo therefore
cannot notice a guide change on its own. The workflow is:

1. Add/rename/remove the part in `interactive-courses` (its `_data/series/*.yml` is the
   source of truth for numbering, permalinks and `legacy` URLs).
2. In this repo: `ruby scripts/sync-guides.rb /path/to/interactive-courses`.
3. Commit the regenerated `_data/guide_index.yml` and any new stubs.

Editing `_data/guide_index.yml` or the stubs by hand will be overwritten by the next sync.

### Page shapes

1. **Markdown + layout** (`ai/*.md`, `about.md`, section hubs, `blog/index.md`). Uses
   `_layouts/page.html` or `_layouts/section-hub.html`. Normal Jekyll.
2. **Field notes and blog posts** (`robotics/**/index.md`, `vision/notes/*/index.md`,
   `blog/**/index.md`). Layout comes from `defaults:` in `_config.yml`, not from front
   matter. Each carries `section`, `group`, `order` and `date_label`;
   `_includes/note-list.html` generates the listings from those.
3. **Static redirect stubs** (the old guide paths — `ai/llm-training/**`, `math/**`,
   `vision/multi-view-geometry/**`, the root-level `*.html` legacy URLs, ~319 files).
   These are plain HTML with a `<meta http-equiv="refresh">` and a visible link, generated
   by `scripts/sync-guides.rb`. They deliberately have **no front matter**, so Jekyll copies
   them verbatim and the linter skips them. Never hand-edit one.

### Cross-repo links are absolute

This repo and `interactive-courses` are separate GitHub Pages projects, so
`relative_url` cannot reach across them. Anywhere this repo links to a guide, use the
absolute `https://denimpatel.github.io/interactive-courses/...` URL — the homepage cards
take it straight from `guide_index.yml`. Nowhere in this repo should a guide link go
through `relative_url`.

### URLs and `baseurl`

The site is served under `baseurl: /AI`, so **every** internal link must go through
`relative_url`; a bare `href="/foo/"` will 404 in production. Runtime JS must get its URLs
from Liquid too.

**Never break a URL.** Every page that has ever had a public URL carries it in
`redirect_from:`, and `jekyll-redirect-from` emits a stub at the old path. If you move a
page within this repo, add its old permalink to `redirect_from` and rewrite inbound
internal links. If a page moved to the guides repo, the generated static stub covers it —
do not also add a `redirect_from`, which cannot cross repos.

### Front matter must be quoted

Four files previously had unquoted `description:` values containing `": "`, which is
invalid YAML and silently broke their meta descriptions. Quote every string value.

## Assets

`assets/css/styles.css` is the whole design system. `assets/js/reveal.js` is the only JS
this repo ships: `_includes/site-nav.html` loads it for the homepage card animations, so
it is kept here even though it is also part of the guide kit. `assets/favicon.svg` and the
`_includes/{site-nav,favicon,guide-footer}.html` chrome are duplicated in the
interactive-courses repo rather than extracted to a submodule — keep the two copies in
sync when you change shared chrome.

There are no local images — **all 31 raster images are hotlinked to
`roboticswithdenim.wordpress.com`** and will disappear if that blog goes down.

## Blog

`/blog/` (see `blog/index.md`) is the landing page for informal writing. It aggregates
`_data/note_groups.yml` across `robotics`, `vision` and `blog` using the same
`note-list.html` include the section hubs use, so a new note shows up there automatically.
New posts are scaffolded with:

```bash
scripts/new-note.sh <section> <group> <slug>
```

Use an existing section/group when the post fits; for pure-opinion posts that fit neither
subject use `scripts/new-note.sh blog perspective <slug>`, which renders under the
"Perspectives" heading on `/blog/`.

## Conventions

- The `theme:` key is explicitly `null`. The `github-pages` gem injects
  `jekyll-theme-primer` by default; every layout here is local, so it is disabled.
- `Gemfile.lock` is gitignored — GitHub Pages resolves its own gem set.
- Robotics notes keep their original informal blog voice ("hey buddy"). Don't rewrite it.
